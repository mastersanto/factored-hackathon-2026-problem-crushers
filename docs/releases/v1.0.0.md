## What the system does

- **Explains a charge the customer doesn't recognize**, from the bank's own records. Every statement is marked as verified (with its record), an estimate, or policy (with its rule). A calibrated fraud-risk estimate sets the case's priority ([specs/001](../../specs/001-dispute-intake-assistant/)).
- **Checks whether a "call from the bank" was real**, against the bank's outbound-contact record. A contact that asked for a code is always a scam.
- **Files a complete claim.** It reaches a specialist as a structured case with verified facts, the customer's rights, and the country's legal deadline, never a raw transcript. Charges under compliance review are never explained.
- **Gives the customer a PDF of the conversation**, with a check code the bank can verify, while keeping only fingerprints. Codes and card numbers the customer typed are masked ([specs/002](../../specs/002-chat-transcript-pdf/)).
- **Works in the customer's language** (English, Spanish, or Portuguese) at phone width, and is accessible by keyboard and screen reader ([specs/003](../../specs/003-ui-improvements/), [004](../../specs/004-browser-language/), [005](../../specs/005-suggestions-language/)).
- **Shows where the inquiry stands, and replies to what was actually asked**: search replies, "my last movements", greetings, and help ([specs/006](../../specs/006-inquiry-progress/), [007](../../specs/007-reactive-replies/)).
- **Is built the way a bank would want**:
  - a deterministic workflow, with models only at the edges (Claude Haiku 4.5 understands, Sonnet 5.5 rewords) and a faithfulness check;
  - permissions in the tool layer;
  - a rules mode with the same guarantees;
  - a protected `main` with pull-request checks, and a tagged release for every deployment ([specs/008](../../specs/008-github-practices/)).

## Results on held-out cases

From [`docs/evaluation.md`](../evaluation.md): 180 Spanish and Portuguese cases per set, tied to real records, with the expected outcome written before the run.

| | Rules only | With Claude (3 runs) |
|---|---:|---:|
| Correct outcome | 85.0% | 95.6% (95.0–96.1) |
| Missed transfers | 28.3% | 2.2% (1.7–3.3) |
| Unsafe outcomes | 0 | 0 |
| Latency p95 per turn · cost per case | 0.12 s · $0 | 3.7 s · $0.0033 |

- **English** (rules mode): 93.3% correct on the held-out set, with 0 unsafe outcomes.
- **The learned fraud-risk estimate** catches 281 of 494 test-period frauds at 100% precision, against 205 for the bank's fixed rule.
